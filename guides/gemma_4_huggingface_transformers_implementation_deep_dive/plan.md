# Gemma 4 HuggingFace Transformers Implementation Deep Dive -- Plan

## Audience

This guide is for engineers who need to understand every PyTorch module and file in the HuggingFace `transformers/models/gemma4/` package in order to port the model to TTNN or modify its architecture. Readers are expected to be familiar with PyTorch `nn.Module` conventions, transformer attention mechanisms, and the general HuggingFace Transformers library structure (config classes, `PreTrainedModel`, processors). No prior knowledge of Gemma 3, Gemma 3n, Mixtral, or the HuggingFace modular inheritance system is assumed -- the guide will explain all inherited behavior inline.

### Chapter 3: Vision Encoder

Covers the complete vision pipeline from patch embedding through spatial pooling, including the 2D factored RoPE.

**Files:**
- `index.md`
  - Module tree: `Gemma4VisionModel` -> `Gemma4VisionPatchEmbedder` + `Gemma4VisionEncoder` (containing `Gemma4VisionEncoderLayer` x16) + `Gemma4VisionPooler`
  - `Gemma4VisionPatchEmbedder`: linear projection of flattened 3xPxP patches (no conv), learned 2D position embedding table of shape [2, 10240, 768] using one-hot position encoding, pixel normalization `2*(x-0.5)`, position embedding via sum over x/y dimensions, padding position zeroing
  - `Gemma4VisionRotaryEmbedding` (extends `LlamaRotaryEmbedding`): computes independent inv_freq for each spatial dimension using `head_dim//2` (not splitting global inv_freq), `forward()` loops over 2 spatial dims and concatenates cos/sin
  - `apply_multidimensional_rope`: splits input tensor into ndim parts, applies standard rotary to each part with its own cos/sin, concatenates results
  - `Gemma4VisionAttention` (extends `Gemma3Attention`): replaces linear projections with `Gemma4ClippableLinear`, adds `v_norm` (RMSNorm without scale), removes `attn_logit_softcapping` and `sliding_window`, sets `scaling=1.0` and `is_causal=False`, applies 2D multidimensional RoPE to Q and K
  - `Gemma4VisionMLP` (extends `Gemma3MLP`): gated MLP with `Gemma4ClippableLinear` for gate/up/down projections
  - `Gemma4VisionEncoderLayer` (extends `Gemma3DecoderLayer`): pre-norm -> attention -> post-attn-norm -> residual -> pre-ff-norm -> MLP -> post-ff-norm -> residual; no cache
  - `Gemma4VisionEncoder`: holds rotary embedding and layer list, creates bidirectional attention mask, runs all layers
  - `Gemma4VisionPooler`: `_avg_pool_by_positions` using one-hot kernel index grouping for kxk spatial pooling, scales output by `sqrt(hidden_size)`; strips padding via pooler mask
  - `Gemma4ClippableLinear`: wraps `nn.Linear` with optional input/output clamping via registered buffers (bounds loaded from checkpoint)
  - End-to-end data flow diagram with tensor shapes at each stage

### Chapter 4: Audio Encoder

Covers the conformer-based audio encoder from mel spectrogram extraction through output projection.

**Files:**
- `index.md`
  - Module tree: `Gemma4AudioModel` -> `Gemma4AudioSubSampleConvProjection` + `Gemma4AudioRelPositionalEncoding` + `Gemma4AudioLayer` x12 + output linear projection
  - `Gemma4AudioSubSampleConvProjection`: two `Gemma4AudioSubSampleConvProjectionLayer` stages (Conv2d kernel=3, stride=2, padding=1 -> LayerNorm -> ReLU), each halves the time dimension; final linear projection from flattened `(channels[0]//4)*channels[1]` to hidden_size=1024; processes mel spectrogram as 2D (time x frequency) with channel dim=1
  - `Gemma4AudioSubSampleConvProjectionLayer`: single Conv2d + LayerNorm + ReLU, mask propagation via stride-2 downsampling
  - `Gemma4AudioRelPositionalEncoding`: sinusoidal relative position encoding for context_size=24 (chunk_size=12 + context_left-1=12 + context_right=0), produces [1, 13, 1024] with concatenated sin/cos layout
  - `Gemma4AudioAttention`: chunked local attention with relative position bias; `_convert_to_block` splits sequence into non-overlapping chunks of size 12; `_extract_block_context` creates overlapping context windows of size 24; relative key projection + `_rel_shift` for relative position shift (Transformer-XL style); softcap via `tanh(logits/cap)*cap`; per-dim scale on queries; q_scale includes `head_dim^-0.5 / log(2)`, k_scale includes `log(1+e)/log(2)`
  - `Gemma4AudioFeedForward`: pre-norm -> Clippable linear (hidden -> 4*hidden) -> SiLU -> Clippable linear (4*hidden -> hidden) -> gradient clipping -> post-norm -> scale by residual_weight=0.5 -> residual add
  - `Gemma4AudioCausalConv1d`: extends `nn.Conv1d` with left-padding for causal behavior, computed from effective kernel size
  - `Gemma4AudioLightConv1d`: pre-norm -> Clippable linear (hidden -> 2*hidden) -> GLU -> depthwise causal Conv1d (kernel=5, groups=hidden) -> gradient clip -> conv_norm -> SiLU -> Clippable linear (hidden -> hidden) -> residual add
  - `Gemma4AudioLayer`: the full conformer block: FFW1 -> pre-attn norm -> attention -> post-attn norm + residual -> LightConv1d -> FFW2 -> final norm; gradient clipping at each stage
  - `Gemma4AudioModel.forward`: subsample conv projection -> rel pos encoding -> bidirectional mask with sliding window -> convert to blocked 5D mask -> run layers -> output linear (1024 -> 1536)
  - End-to-end data flow diagram with tensor shapes

### Chapter 5: Text Decoder

Covers the text decoder including the dual-type attention (sliding vs global), MoE blocks, per-layer input embeddings, and KV sharing.

**Files:**
- `index.md`
  - Module tree: `Gemma4TextModel` -> `Gemma4TextScaledWordEmbedding` + `Gemma4TextDecoderLayer` x30 + `Gemma4TextRotaryEmbedding` + RMSNorm + optional per-layer embedding infrastructure
  - `Gemma4TextScaledWordEmbedding` (extends `Gemma3TextScaledWordEmbedding`): standard embedding scaled by `sqrt(hidden_size)`
  - `Gemma4TextRotaryEmbedding` (extends `Gemma3RotaryEmbedding`): maintains separate inv_freq buffers per layer type (sliding_attention: default rope theta=10000; full_attention: proportional rope with theta=1M, partial_rotary_factor=0.25)
  - `Gemma4TextAttention`: dual head dimensions (head_dim=256 for sliding, global_head_dim=512 for global); k_eq_v mode where V projection is removed and K output is reused as V; KV sharing across layers (last N layers share KV projections with earlier layers of the same type via `past_key_values.shared_layers`); `store_full_length_kv` flag for source layers; sliding_window=512 for sliding layers; q_norm, k_norm, v_norm (without scale); scaling=1.0
  - `Gemma4TextMLP` (extends `Gemma3MLP`): gated MLP, optionally double-width for KV-shared layers (`use_double_wide_mlp`)
  - `Gemma4TextExperts` (extends `MixtralExperts`): batched expert computation with fused gate_up_proj, holds all expert weights
  - `Gemma4TextRouter`: RMSNorm (no scale) -> per-expert-scale-aware routing; softmax -> topk -> normalize weights -> per_expert_scale multiplication
  - `Gemma4TextDecoderLayer` (extends `Gemma3DecoderLayer`): input_layernorm -> attention -> post_attention_layernorm -> residual -> pre_feedforward_layernorm -> MLP; when MoE enabled: routes pre-MLP residual through router+experts in parallel with MLP, combines via `post_feedforward_layernorm_1(mlp_out) + post_feedforward_layernorm_2(moe_out)`; per-layer input embedding: gate -> activation -> element-wise multiply with per_layer_input -> project -> norm -> residual; layer_scalar buffer
  - `Gemma4TextModel.forward`: creates separate causal masks for full_attention and sliding_attention; computes position embeddings per layer type; per-layer input embeddings: `embed_tokens_per_layer` produces [B, S, num_layers, hidden_size_per_layer_input], `project_per_layer_inputs` projects main embeddings and combines with per-layer token embeddings; passes per_layer_input slice to each decoder layer
  - Attention mask creation: `create_causal_mask_mapping` produces a dict mapping layer type to mask; for `use_bidirectional_attention="vision"`, vision tokens get bidirectional attention via `token_type_ids_mask_function` using `mm_token_type_ids`

- `moe_details.md`
  - Detailed walkthrough of the MoE data path within `Gemma4TextDecoderLayer`
  - Router weight computation: RMSNorm -> scale -> linear -> softmax -> topk -> normalize -> per_expert_scale
  - Expert computation: `MixtralExperts` base class behavior (fused gate_up_proj and down_proj for all experts)
  - How MLP and MoE outputs are combined (parallel paths, summed after separate post-norms)
  - Parameter counts and memory implications

### Chapter 6: Top-Level Model Assembly and Multimodal Embedding

Covers how `Gemma4ForConditionalGeneration` orchestrates vision, audio, and text, and how `Gemma4MultimodalEmbedder` merges modality features into the text embedding space.

**Files:**
- `index.md`
  - Full module tree of `Gemma4ForConditionalGeneration`: `model` (`Gemma4Model`) containing `vision_tower` (`Gemma4VisionModel`), `audio_tower` (`Gemma4AudioModel`), `embed_vision` (`Gemma4MultimodalEmbedder`), `embed_audio` (`Gemma4MultimodalEmbedder`), `language_model` (`Gemma4TextModel`); plus `lm_head` (tied to embed_tokens)

  - `Gemma4PreTrainedModel`: `_init_weights` dispatch table covering all custom module types, supported attention backends (flash, sdpa, flex, eager), no-split modules

### Chapter 7: Preprocessing Pipelines

Covers the processor, image processors (PIL and torchvision backends), video processor, and audio feature extractor.

**Files:**
- `index.md`
  - `Gemma4Processor` (extends `ProcessorMixin`): orchestrates tokenizer, image_processor, video_processor, feature_extractor; `__call__` handles text/images/audio/videos; image token expansion: `<image>` -> `<boi><image_token>*N<eoi>` where N=num_soft_tokens_per_image (dynamic, aspect-ratio-aware); video token expansion with timestamps in mm:ss format; audio token expansion: dynamic count from `_compute_audio_num_tokens` (replicates mel framing + two SSCP conv layers arithmetic); `_get_num_multimodal_tokens` for pre-computation; `create_mm_token_type_ids` for bidirectional masking

## Conventions

1. **Module names**: Always use the full class name (e.g., `Gemma4TextAttention`, not "the attention module"). When referring to an instance within a parent module, use the attribute path (e.g., `self.self_attn`, `self.mlp`).

2. **Config references**: When citing a config parameter, use `ConfigClass.param_name` format (e.g., `Gemma4TextConfig.sliding_window`). Include the default value on first mention.

3. **Inheritance notation**: When a class extends another, write it as `Gemma4VisionMLP (extends Gemma3MLP)` and explicitly state what is overridden versus inherited.

4. **Tensor shapes**: Document tensor shapes in `[dim1, dim2, ...]` notation with named dimensions where helpful (e.g., `[batch_size, seq_len, hidden_size]`). Use the config parameter names for dimension values (e.g., `[B, S, 2304]` for hidden states in the text model).

5. **Layer type terminology**: Use "sliding attention layer" and "global attention layer" (not "local" or "full") to match the `layer_types` config values `"sliding_attention"` and `"full_attention"`.

6. **File paths**: Reference source files using their basename within the gemma4 package (e.g., `modular_gemma4.py`), not the full installed path.

7. **Abbreviations**:
   - MoE = Mixture of Experts
   - RoPE = Rotary Position Embedding
   - SSCP = Sub-Sample Convolution Projection (the audio front-end)
   - FFW = Feed-Forward (in audio conformer context)
   - KV = Key-Value (in attention context)
   - GQA = Grouped Query Attention

8. **Code snippets**: Include only when showing a non-obvious computation (e.g., the relative position shift, the 2D RoPE application, the router weight normalization). Do not reproduce entire forward methods.

9. **TTNN porting notes**: Each chapter should end with a section titled "TTNN Porting Considerations" highlighting aspects relevant to hardware implementation: which operations are non-standard, where numerical precision matters (e.g., gradient clipping, softcap), and where custom kernels may be needed.
